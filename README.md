# 云链进销存（群晖 NAS 版）

一套前后端分离、可私有部署的进销存系统。核心容器为 React Web、Node API 和 PostgreSQL，适合安装了 Container Manager 的群晖 NAS。

## 已实现

- 多用户登录入口与会话 API
- 商品、条码、分类、多商品采购入库和实时库存
- 产品列表的编辑与详情操作已接入真实 API；详情显示完整产品资料和最近库存流水，库存不能绕过流水直接修改
- 每个产品可保存实际所在仓库和库位；现有产品及新建/导入产品默认使用系统设置中的默认仓库。具备产品编辑权限的用户可在库存列表中直接点击新增、修改或清空，列表固定先显示仓库、再显示库位。配货单默认在产品名称后显示库位，也可通过打印属性选择器控制是否打印
- 产品列表显示缩略图；无图商品显示加号，可从本地选择 JPG、PNG 或 WebP 图片上传和更换，单张最大 5MB
- 产品列表支持 Excel 批量导入和导出：可下载标准模板，第一列可按产品行直接插入 JPG/PNG 缩略图，并可填写正数、零或负整数初始库存；空单元格和只含空格的单元格统一按未填写处理，导入前检查必填字段、数字、分类、重复货号/条码及图片锚点、格式和大小，全部通过后在单个事务中新增产品并写入可追溯的初始库存流水，随后上传图片；导出包含产品资料、库存和进销统计
- 产品和分类的编辑窗口提供“删除配图”，确认后会清空数据库图片地址并删除持久化目录中的实际图片文件
- 产品支持“产品名2”；产品列表右上角可自由选择显示列并保存浏览器偏好。入库统计为累计采购入库数量，销售统计为累计净销售数量，库存统计为当前库存
- 产品列不受勾选先后影响，固定顺序为：图片、货号、条码、产品名称、产品名2、分类、箱装数、福林售价、欧元售价、美金售价、入库统计、销售统计、供货商、采购成本、库存统计、创建时间、单位；各列按内容类型限制宽度，长内容在本列内自动换行，不挤压其他属性
- 产品页搜索栏提供真实分类下拉选项，分类来自数据库现有产品，可与货号、条码或名称关键词组合查询
- 货物菜单提供独立“分类”页面，以主分类和子分类两级结构显示全部分类；可维护分类名、分类名2和分类图片，升级时会自动把产品中已有的分类导入为主分类
- 分类页面支持 Excel 导入、标准模板下载和导出；每行包含主分类名/分类名2及可选的子分类名/分类名2，可新增主分类或在现有主分类下批量新增子分类
- 产品页使用主分类、子分类两个联动筛选菜单；只选主分类会查询该主分类及其全部子分类。产品新增和编辑窗口只能从现有分类下拉菜单中选择分类
- 产品列表的分类单元格可点击打开分类选择窗口，通过主分类和可选子分类快速修改产品分类；无产品编辑权限的用户保持只读
- 产品、客户、采购、销售单、配货单、开票、发票、操作日志和员工等列表统一分页显示，每页固定 10 条；筛选、搜索或数据变化后自动回到有效页码
- 产品/库存、分类、客户、入库单、销售单和发票列表提供仅管理员可见的逐行删除。删除采用可审计软删除；删除入库单会冲回入库库存，删除已扣库销售单会恢复尚未退回的库存，存在任何发票记录的销售单禁止删除。发票删除只移除 ERP 内部显示，不调用或改变 Számlázz.hu 的真实发票，并会阻止该销售单重复开票
- 产品和库存列表支持管理员勾选多行或勾选当前页；选中后工具栏显示批量删除按钮，所选产品在同一个数据库事务中统一删除
- 产品名2由迁移 `011_product_name2.sql` 自动增加，已有产品默认留空
- 每个产品支持福林 HUF、欧元 EUR、美元 USD 三个独立销售价格；扫码销售和采集器销售可选择货币，销售单会保存所用货币
- 客户资料、销售单、扫码销售、采集器批量销售与事务化扣减库存
- 客户菜单仅保留客户列表，移除未实现的“客户账目”入口
- “扫码零售/扫码销售”菜单已合并为“扫码销售”；新增“采集器销售”，支持按行接收货号或条码与数量、检查匹配结果、合并重复商品并导入生成真实销售单
- 采集器销售支持逗号或空格分隔、销售备注、正负整数数量和最多 200 种商品；导入成功后自动进入扫码销售并打开刚生成的订单供销售员修改
- 扫码销售可修改采集器刚导入的订单商品、数量、客户和货币；保存时按新旧明细差额事务化调整库存并记录销售修改流水
- 销售单明细窗口，以及用负数销售实现退货入库
- 销售列表的详情列显示订单明细条数，点击数量会在当前页面上方打开订单详情窗口
- 销售单详情弹窗的每个商品行显示产品缩略图和当前实时库存；无图片商品显示占位图标
- 销售单列表操作栏提供编辑图标，管理员和销售员点击后会进入扫码销售并载入原订单，保存修改时更新原订单和库存差额
- 扫码销售的送货信息窗口包含联系电话、车牌号、送货地点和备注；编辑订单时会载入原资料。送货单和配货单在客户名称下显示客户资料中的“公司地址”，不打印订单送货地址
- 销售单列表支持按起止日期查询完整区间，日期边界使用可配置的业务时区
- 销售单列表支持自选显示属性并在浏览器中保存偏好；点击选择框外会自动关闭，操作列始终保留
- 销售单列表默认显示备注栏，长备注在本列内自动换行；备注也可通过列选择器隐藏，并参与销售单关键字搜索
- 管理员和销售员可直接点击销售单列表中的备注进行新增或修改；回车或离开输入框保存，Esc 取消，修改会进入操作日志
- 销售日期默认使用客户端系统当天；清空起止日期后再次查询可显示全部订单
- 销售单列表提供已扣库、已送货和结算状态；状态以对号/叉号显示并可点击切换，其中扣库状态会事务化增减库存并写入流水
- 财务“流水明细”按日期统一展示销售实际收款、销售退款与手工收支，逐笔标明现金、银行转账或历史退款未指定方式；HUF、EUR、USD 分开汇总总收入、总支出、净额以及现金/转账净额。管理员和财务人员可新增收入或支出并选择原因、方式、币种、日期、金额和备注
- 财务菜单仅保留真实的“流水明细”，“订单财务”入口及其旧页面映射已移除
- 销售菜单提供独立“配货单列表”，管理员和仓库员工可按日期查询、打开订单明细并打印无价格配货单；打开打印页后，页面标签和纸张大标题均显示“配货单”。页面和专用只读 API 均不返回当前库存、货币、金额、收款及销售状态信息
- 设置页提供真实的基础信息配置：公司资料、EUR/HUF 与 USD/HUF 换算汇率、默认销售币种、是否允许超卖、低库存预警值、默认仓库和采购/销售单号前缀
- 超卖默认开启，商品库存可以为负数；关闭后，新增销售、修改已扣库销售单和重新扣库都不能使库存低于 0
- 左侧已移除无实际用途的“主控”及其子菜单
- 左侧已移除无实际用途的“App/云店”及其子菜单
- 首页经营概览、库存预警与基础报表入口
- PostgreSQL 持久化、容器健康检查、内部隔离网络
- 桌面和手机浏览器响应式界面
- 多语言框架与语言持久化：简体中文、English、Magyar
- 商品名称/描述的数据库级多语言扩展表与 API
- 前端登录、商品、客户、采购、销售、首页汇总和报表汇总已接入真实 API
- 主导航采用浏览器式多页面标签：菜单会新增或激活页面而不会覆盖旧页面，非活动页面保留查询和表单状态；业务标签可单独关闭，首页固定保留
- 多商品采购入库与扫码销售会事务化更新库存并写入库存流水；采购总价由 API 根据明细计算

- 新建入库单只有货号和正整数数量必填；供货商可空，仓库留空时使用系统默认仓库，采购单价留空按 0 计入本单且不覆盖产品原有采购成本
- 销售数量支持正负整数；负数销售会增加库存并写入库存流水，数量为 0 的明细不能保存
- API 启动时自动执行版本化数据库迁移，已有数据无需重新初始化

- 迁移 `023_role_permissions.sql` 自动创建角色权限表，并按升级前的角色限制写入默认权限；员工管理和操作日志固定仅管理员可见

## 增加新语言

1. 在 `web/src/i18n.jsx` 的 `locales` 中登记语言代码。
2. 在同一文件的 `messages` 中增加翻译词典；未翻译的键会安全回退到简体中文。
3. 在数据库 `supported_locales` 中登记语言；商品内容翻译保存到 `product_translations`，无需修改商品主表。
4. 所有新界面文案必须通过 `t("key")` 使用语言键，规则已经记录在前端 `AGENTS.md`。

## 群晖部署

DS1517+ 与 DSM 7.1.1 用户请优先阅读 [`README-DS1517+.md`](README-DS1517+.md)，并使用 `docker-compose.ds1517.yml`。

1. 将整个 `erp-nas` 目录上传到 NAS，例如 `/volume2/docker/erp-nas`。
2. 将 `.env.example` 复制为 `.env`，替换其中所有密码和密钥。
3. 在 Container Manager 新建“项目”，来源选择此目录中的 `docker-compose.yml`。
4. 构建并启动后访问 `http://NAS-IP:8088`。
5. 使用 `.env` 中的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 登录。

已有安装升级时不要删除 `data/postgres` 或 `data/product-images`。覆盖项目文件后再次运行部署脚本，API 会自动执行尚未应用的迁移；管理员密码仍以 NAS `.env` 中的 `ADMIN_PASSWORD` 为准。

如需公网访问，建议使用群晖反向代理绑定域名并启用 Let's Encrypt HTTPS；数据库和 API 不应直接暴露公网端口。

## 数据备份

定期备份 Docker 卷 `postgres_data` 和 `product_images`。群晖部署需要同时备份 `data/postgres` 与 `data/product-images`；升级前建议额外执行 PostgreSQL 逻辑备份。

## 本地前端预览

前端目录为 `web`。本地开发需要同时运行 API 与 PostgreSQL；Vite 会把 `/api` 代理到本机 `3000` 端口。登录账号由本地或 Docker 环境变量中的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 控制，不再提供前端演示登录。

## 销售结算

- 销售单列表显示实付、欠款和结算状态：红色叉号表示未付款，黄色时钟表示未付完，蓝色对号表示已结清。
- 点击未付款或未付完状态进入订单结算页，可选择现金或银行转账，并支持部分收款和全部结清。
- 每次收款都会保存为独立记录；系统根据累计实付自动计算欠款及结算状态。已有收款记录的销售单不能再修改商品、币种或总额。

## Számlázz.hu 电子发票

- 开票工作台提供“一键开发票”。现有 HUF/EUR/USD 销售价按不含税价处理，发票统一使用 27% ÁFA，并展示不含税、税额和含税合计预览。
- “发票 → 开票”页采用销售单列表布局，默认显示当天全部销售单并支持起止日期查询；每单显示发票状态，已开票或处理中时开票按钮置灰。更正、单独作废和已作废后的重开统一放在“发票列表”；作废成功后不会自动重开。
- 已取得号码的发票永不删除或覆盖。迁移 `016_invoice_lifecycle.sql` 将销售单与发票改为一对多，保存普通、更正、作废、重开发票之间的关联、客户快照、原因及各自PDF。
- 开票弹窗会只读显示销售单的不含税单价，并提供独立、可修改的开票单价；价格比例统一使用 `100%`、`33.33%`、`25%` 等百分数，可批量计算开票单价，且不会回写销售单或改变库存。
- 默认生成电子发票且 `sendEmail=false`，不会由 Számlázz.hu 自动发送客户邮箱。成功后系统保存发票号码和 PDF，发票列表支持登录后打印及下载。
- 现金发票默认当天到期并标记已付款；银行转账默认 8 天付款期限。EUR/USD 使用系统设置中的 HUF 汇率及 `MNB` 作为汇率来源。
- 客户开票资料包括名称、邮编、城市、详细地址、国家、税号、邮箱和电话。名称、邮编、城市及详细地址为开票必填项。
- 迁移 `015_szamlazz_invoices.sql` 自动增加客户开票字段、发票及发票明细快照。开票尝试后销售单锁定，避免开票数据与订单再次变化；失败重试会先按外部标识查询 PDF，降低网络超时造成重复开票的风险。
- Agent Key 仅通过 API 容器的 `SZAMLAZZ_AGENT_KEY` 环境变量读取，禁止写入代码、数据库或 Git。

## 送货单

- 扫码销售点击保存订单后，会先弹出送货信息窗口，可填写联系电话、车牌号和送货地点。
- “保存并打印”会原子化保存订单和送货信息，并打开包含订单、客户、公司地址、联系电话、车牌及全部商品明细的送货单页面；订单送货地址继续保存但不打印。
- 送货单工具栏可选择打印时显示的商品属性，包括货号、条码、产品名、产品名2、当前库存、数量、单价和小计；选择会保存在当前浏览器。
- 送货单支持 A4 纵向打印；销售单列表的打印按钮可以随时重新打开历史送货单。
# 报表中心

报表中心包含销售、财务和客户三个真实业务报表。可按日期、单一币种及各报表业务属性组合筛选，查看关键指标、趋势、排行和逐笔明细，并导出 Excel。销售报表按销售/退款发生日期统计；财务报表按实际资金流水统计；客户报表同时展示期间购买表现和当前欠款。
